EvoGuard

Evidence-driven control for AI-assisted code changes

Trustworthy AI Code provenance PR quality gate

github.com/modarresi1913/Evoguard ↗

A context-aware gate between AI code generation and your main branch. Every AI-touched pull request is evaluated against the codebase's history, contracts, dependencies, tests, conventions, and security constraints — and either explained or blocked before merge. Built as a self-deployable template (Next.js / TypeScript / Tailwind).

Problem: AI-generated code reaches main with no inspectable chain of evidence. EvoGuard asks what it would take to make every AI-touched change reviewable before merge.

Maturity (from repo): Self-deployable template; reference implementation. No production-readiness claim is made beyond what the repository demonstrates.

OrganoidOS

Open operating-system specification for biological neural computing

New Computing Substrates Open spec Reference emulator

github.com/modarresi1913/OrganoidOS ↗

An open operating-system layer for biological neural networks — cultured cortical organoids, MEA-coupled cultures, and the in-silico models that approximate them. Ships a versioned specification and a reference emulator. No biological result is claimed.

Problem: biological neural networks exhibit properties no current silicon substrate replicates, yet there is no shared OS layer for experimenting with them. OrganoidOS proposes one as an open, forkable specification.

Maturity (from repo): v0.1 stable spec + L0 reference emulator (CI green across Python 3.9–3.12). v1.0 target: multi-vendor conformance (≥2 independent L1 implementations). No biological experiment is claimed.

Neuro-Continuum

Context-adaptive, safety-aware AI interaction architecture

Trustworthy AI Agents Falsifiable

github.com/modarresi1913/neuro-continuum-ai ↗

An experimental architecture that estimates probabilistic interaction states from observable signals and dynamically selects safer, more useful response policies. Every number in the demo is labelled ESTIMATE, never DIAGNOSIS. The core hypothesis is explicitly falsifiable.

Problem: stateless AI treats two users with identical prompts identically, even when their interaction states differ. The architecture explores whether context estimation improves interaction quality — and surfaces cases where it does not.

Maturity (from repo): Experimental architecture + browser demo. Release v0.1.0. Tests reported passing on the repository; not a validated result.

Hanna AI

Multi-agent swarm for petroleum & petrochemical trading

Agents for Real Systems Multi-agent Workflow

github.com/modarresi1913/hanna-ai ↗

A multi-agent system for the petroleum and petrochemical trading industry. Six specialized agents — Market Analyst, Logistics Coordinator, Documentation Expert, Compliance Officer, Finance Advisor, Operations Manager — collaborate across the trade lifecycle: market analysis, logistics, compliance, documentation, and financial settlement.

Problem: a single trade touches markets, maritime logistics, sanctions screening, contract documentation, letters of credit, and cargo insurance. Siloed tools lose the through-line. Hanna AI explores whether a coordinated agent swarm can preserve traceability across the full workflow.

Maturity (from repo): Production-grade codebase (Next.js 16 / TypeScript / Prisma). Whether it is deployed in any specific environment is not claimed here.

Onturgy

An open-source philosophy of architecture for the age of AI

Theory Audit framework Forkable

github.com/modarresi1913/onturgy ↗

An open-source philosophical program that treats platforms, protocols, institutions, and AI systems as things that construct, constrain, distribute, and transform practical possibility. It provides a possibility-graph model, a six-dimension audit kernel, an audit instrument, a method (ONTacture) for testing commitments by building them, a lineage graph for the architects themselves, and an explicit list of conditions under which the program would fail.

Problem: architectures shape what their inhabitants can do, yet the assumptions that govern that shaping are rarely made inspectable. Onturgy asks: what must an architecture make explicit if it is to remain revisable by those it affects?

Maturity (from repo): v2 (per repository). The README describes four "empirical passes"; the repository's own badge reads "empirically tested". This is a philosophical and audit framework, not a software product, and its claims should be read on its own terms.

Kintsugi

Clinical evidence fragility mapper

Trustworthy AI Argumentation Zero-dependency

github.com/modarresi1913/kintsugi-clinical-fragility ↗

A zero-dependency, single-file research tool (~515 lines) that decomposes a clinical claim into its supporting and attacking arguments, then computes a Fragility Index (F) quantifying how provisional each part of the reasoning is. An MVP instantiation of a Fragility-Aware Reasoning Architecture based on QBAF-style bipolar argument graphs.

Problem: a clinical claim can be net-supported yet highly fragile — meaning it looks settled only because its weak points have not yet been tested. Kintsugi makes the cracks visible rather than smoothing them over.

Maturity (from repo): Research prototype, v0.1, MIT-licensed. The repository explicitly labels itself a research prototype; it is not a clinical decision tool.
